# 理财系统收束与现金流决策闭环设计稿

日期：2026-10-15

状态：已确认，执行中

## 目标

将系统收束为“家庭现金流决定可投资额度，持仓与市场信号决定投资动作，决策结果可复盘”的日常理财闭环。首轮不删除数据库数据或后端能力，避免未验证的清理造成历史数据和维护能力丢失。

## 审计结论

- 前端导航包含 35 个可达页面，日常投资、家庭财务和研发治理混排，降低了高频路径的可发现性。
- 支出数据层已经存在于未提交工作区：`expense_records`、CRUD、月度汇总、趋势、固定项复制及画像回填已实现；但尚未接入前端、家庭财务看板、实时仓位计算和对话上下文。
- `family-finance`、`goal-buckets`、`health-v2` 已提供家庭财务、目标分桶与全账户体检能力，适合成为收支记录的归属，而非另建独立记账系统。
- 系统已有功能使用埋点。页面隐藏并不等同于代码删除；删除必须以 30 天使用数据、静态依赖扫描和冒烟测试共同确认。

## 不做的事

- 不建设完整复式记账、账户对账、票据识别或报税能力。
- 不将“当月全部结余”自动视为可投资金额；应先扣除资金桶缺口和预留现金。
- 不在本轮删除表、历史记录、Agent 或后端 API。
- 不改变现有未提交的支出数据层契约，除非发现实际集成缺陷。

## 用户信息架构

主导航调整为五个面向结果的区域：

1. 今日行动：每日看板、AI 对话、风险与提示、决策档案。
2. 资产与持仓：持仓、交易、智能补仓、配置偏离、收益与行为复盘。
3. 家庭现金流：财务总览、支出记录、资金桶、全账户诊断。
4. 市场与机会：估值数据、机会雷达、市场热点、债市分析。
5. 知识与研究：文章、资料、个人文档与蒸馏知识。

研发治理入口合并为默认折叠的“系统治理”：Agent 管理、分析记录、调用成本、系统配置、数据健康、质量评测、影子模式、能力中心和使用分析。RAG 调试入口从主导航移出。

首轮隐藏而非删除：旧版健康分、RAG 分析及测试、评测集、Bad Case、质量看板、Shadow Mode、Token 用量、数据健康、功能分析、策略沙盒。策略回测仍保留在资产与持仓的二级入口。隐藏页面保留其路由/组件，以支持直接访问和回退。

## 现金流闭环

```text
月收入 + 支出明细
        -> 当月结余（实际记录优先，画像均值兜底）
        -> 现金流概览
        -> 资金桶缺口与必要预留
        -> 建议可投资额度
        -> 智能补仓 / 决策中心的金额上限
        -> 决策档案与执行结果
```

### 数据规则

- 支出以月份、分类、金额、固定项和备注记录；固定项可复制至新月份。
- “当月实际支出”优先于画像中的 `monthly_expense`；无当月记录时再使用近三个月均值回填值。
- 月结余等于月收入减当月支出，允许为负值并明确提示不可追加风险资产。
- 可投资额度采用保守上限：`max(0, 月结余 - 本月资金桶补足额 - 安全缓冲)`。第一阶段将安全缓冲固定为 0，先透明展示组成项；待连续数据充分后才引入可配置缓冲。
- 支出记录写入后继续更新 `user_profiles.monthly_expense` 与 `monthly_surplus`，以保持既有 Agent 和服务兼容；实时消费者应改读现金流摘要，以避免将历史均值误作当月事实。

### UI 设计

在“家庭财务总览”中增加一个“本月现金流”区块：收入、已记录支出、可结余、支出来源和“记录支出”主操作。点击后进入同一组件的支出管理视图，而不是增加顶级页面。

支出管理视图提供：月份选择、固定/浮动支出切换、类别选择、金额和备注、新增/编辑/删除、固定项复制、分类汇总与六个月趋势。删除使用现有 `ConfirmDialog`。空状态引导先录入固定支出。

资金桶页和决策中心显示可投资额度来源，并在额度为零时阻止或降级“运行投资决策”的下单金额建议；决策研究与回测不受影响。

## 分阶段实施

### 第一阶段：可用的现金流闭环

1. 完成支出 API 的单元与路由测试，修正集成缺口。
2. 增加前端 API 封装和支出管理组件，并嵌入家庭财务总览。
3. 家庭总览使用实时现金流数据；资金桶和仓位计算读取统一的可投资额度。
4. 导航重组并隐藏低频研发页，保持已隐藏页面可直接访问。
5. 扩展对话上下文，让 AI 明确区分当月真实支出与历史均值。

### 第二阶段：基于证据的精简

1. 连续 30 天采集页面使用、错误和直接访问数据。
2. 对候选功能进行静态依赖扫描、API 调用扫描和冒烟测试。
3. 只删除零使用、无代码消费者、无运营依赖的前端组件和路由。
4. 每项删除单独提交，并保留迁移说明；数据库表仅在更长观察期后另立方案处理。

## 错误处理与安全

- 金额和月份由后端验证；错误以 HTTP 400 返回，前端显示服务端消息。
- 支出删除必须二次确认；前端提交期间禁用重复操作。
- 现金流/资金桶/仓位计算失败时，展示明确的“数据暂不可用”，不得回退为虚构建议金额。
- 资金不足时可以继续查看分析、生成研究结论和复盘，但不得推荐额外风险资产投入。

## 验证策略

- 后端：覆盖支出 CRUD、月份/金额/类别校验、固定项幂等复制、实际支出优先级、画像回填和仓位额度上限。
- 前端：覆盖 API 参数、支出组件的录入/删除确认/空状态，以及导航与页面注册一致性。
- 集成：启动应用，验证家庭总览、支出记录、资金桶、智能补仓和决策中心形成完整链路。
- 回归：运行现有前后端测试和构建；检查隐藏页面仍可通过 `activePage` 正常挂载。

## 风险与回滚

第一阶段新增数据只写入独立的 `expense_records` 表；隐藏导航为可逆配置改动。若现金流联动异常，可关闭 `expense.auto_fill_profile` 并让既有模块继续读取画像静态字段；不删除任何用户记录。
