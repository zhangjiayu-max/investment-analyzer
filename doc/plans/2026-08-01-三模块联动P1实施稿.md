- 无 FED 模型、期限利差、M2/社融维度

### 改动点

**1.1 regime 阈值配置化**（`portfolio_fact_layer.py:212-260`）
- 新增配置：`opportunity.regime.bear_pct`（默认 30）、`opportunity.regime.bull_pct`（默认 70）

- 评分规则（全部走配置）：
  - bear + 防御主题（债券/红利）→ +5

  - bull + 高估值（百分位 >70）→ -8（regime gate）
  - sideways → 0
- 主题分类走 `opportunity.regime.theme_category` JSON 配置（key=主题，value=offensive/defensive/neutral）

**1.3 FED 模型维度（轻量）**（`opportunity_engine.py`）

- 调用工具 `get_bond_yield_curve`（已存在 tools/__init__.py:403）
- 输出 `fed_model_zscore`，作为 regime 的辅助维度
- 开关 `opportunity.macro.fed_model_enabled`（默认 false，遵循新增 LLM/外部数据开关默认 false 原则）

**1.4 confidence 联动**（`decision_pipeline.compute_confidence`）
- 新增入参 `regime`
- bear regime 下 `confidence × 0.9`（防御性折扣，走 `opportunity.regime.bear_confidence_discount` 配置，默认 0.9）

### 新增配置

## 任务 2: R6 含成本 walk-forward 回测

### 现状
- `review_opportunity_backtests` (L2147-2270) 用裸 `change_pct`，无成本、无滑点、无 Sharpe/Calmar/最大回撤
- `fee_calculator.py` 已实现（P0 前已存在），未被 opportunity_engine 引用
- `theme_opportunity_backtests` 表无 `dim_scores_json / net_return / sharpe / max_drawdown / entry_amount` 字段

### 改动点

**2.1 扩展回测表**（`db/opportunities.py:_ensure_column`）
新增列（`_ensure_column` 已是 IF NOT EXISTS 模式，安全）：
- `dim_scores_json TEXT`（14 维分项分快照，供 R4 算 IC）
- `entry_amount REAL`（决策金额，算 Sharpe 用）
- `buy_fee REAL` / `sell_fee REAL`（实际扣费）
- `slippage_cost REAL`（滑点成本）
- `net_return REAL`（扣成本后净收益）
- `max_drawdown REAL`（持有期内最大回撤）
- `sharpe REAL`（夏普比率，年化）
- `calmar REAL`（Calmar 比率）

**2.2 回测扣成本**（`opportunity_engine.review_opportunity_backtests`）
- import `from services.fee_calculator import calc_buy_fee, calc_sell_fee`
- 持有期 = review_date - entry_date，走 `fee_calculator._sell_rate_by_holding`
- **关键决策**：15 日持有期会落入 lt7d 1.5% 惩罚费率区间，对机会信号不公平。**新增 `opportunity.backtest.fee_mode` 配置**：
  - `realistic`（默认）：按实际阶梯费率
  - `relaxed`：机会信号回测豁免 lt7d 惩罚，按 lt1y 0.5% 计算
- `net_return = change_pct - buy_fee_pct - sell_fee_pct - slippage_bps*2`

**2.3 滑点建模**
- 新增 `opportunity.backtest.slippage_bps`（默认 5bps）
- `adj_entry = entry_price × (1 + slippage/10000)`
- `adj_review = review_price × (1 - slippage/10000)`

**2.4 风险指标计算**
- 调用 `portfolio_risk._fetch_closes(index_code, days)` 取持有期日频价格
- 算 max_drawdown（持有期内峰值到谷值）
- 算 sharpe = (annualized_return - rf) / annualized_vol，rf 走 `opportunity.backtest.risk_free_rate`（默认 0.02）
- 算 calmar = annualized_return / max_drawdown

**2.5 walk-forward 滚动回测**（新增函数 `run_walk_forward_backtest`）
- 入参：theme, start_date, end_date, window_days=15, step_days=5
- 逻辑：按 step_days 滚动取 window_days 窗口，每个窗口算一个 entry/review 对
- 输出聚合：`{theme, windows_count, hit_rate, avg_net_return, avg_sharpe, avg_max_drawdown}`
- 新增表 `theme_backtest_metrics`（per theme + per window 聚合）

**2.6 命中判定调整**
- 原 `excess_return >= 2%` 改为 `net_excess_return >= opportunity.backtest.hit_threshold`（默认 1.5%，因扣成本后门槛应降低）

### 新增配置
```
opportunity.backtest.fee_mode = realistic  # realistic / relaxed
opportunity.backtest.slippage_bps = 5
opportunity.backtest.risk_free_rate = 0.02
opportunity.backtest.hit_threshold = 1.5
opportunity.backtest.walk_forward_enabled = false  # 默认关闭，手动触发
opportunity.backtest.walk_forward_window_days = 15
opportunity.backtest.walk_forward_step_days = 5
```

### 新增表
```sql
CREATE TABLE IF NOT EXISTS theme_backtest_metrics (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    theme TEXT,
    window_start TEXT,
    window_end TEXT,
    windows_count INTEGER,
    hit_rate REAL,
    avg_net_return REAL,
    avg_sharpe REAL,
    avg_max_drawdown REAL,
    avg_calmar REAL,
    created_at TEXT DEFAULT (datetime('now','localtime'))
);
```

## 任务 3: R4 信号 IC 加权置信度

### 现状
- `_score_theme` 14 维硬编码加分，无权重字典、无 IC
- `_apply_hit_rate_feedback` 只做粗粒度 3 次 miss 降权 20%
- `theme_opportunity_backtests` 表无 `dim_scores_json`（R6 已扩展）
- `compute_confidence` 未引入 IC

### 改动点

**3.1 14 维权重字典化**（`opportunity_engine._score_theme`）
- 提取 14 维名称为常量：`DIMENSIONS = ["news", "policy", "valuation", "holding", "tradability", "tech", "capital", "sentiment", "leading", "volume", "research", "margin", "etf", "basic"]`
- 每维加分逻辑保持不变，但最终 `score += dim_score × weight`
- 权重从 `opportunity.weight.dim_{name}` 配置读取（默认 1.0，等权）
- 输出 `dim_scores_json`（dict 形式）写入回测表

**3.2 IC 计算**（新增 `db/opportunities.py:calc_signal_ic`）
- 函数签名：`calc_signal_ic(dim_name: str, window_days: int = 90) -> float`
- 逻辑：取最近 window_days 内已 review 的回测记录，对 (dim_score, net_excess_return) 算 Spearman rank correlation
- 用 `scipy.stats.spearmanr`（项目已用 numpy，scipy 需确认，无则用纯 Python 实现 rank correlation）
- 缓存 1 小时（避免每次评分都算）

**3.3 IC 反哺权重**（扩展 `_apply_hit_rate_feedback`）
- 新增逻辑：每 N 次回测后（默认 10 次），重算各维 IC
- IC > 0.1 → weight × 1.2（上限 2.0）
- IC < 0 → weight × 0.8（下限 0.3）
- IC < -0.05 → weight = 0（禁用该维度）
- 保留原"3 次 miss 降权"作为快速反馈，IC 作为慢速精调
- 写入 `opportunity_weight_log` 表（已存在）

**3.4 confidence 融合 IC**（`decision_pipeline.compute_confidence`）
- 新增入参 `dim_scores_json`、`ic_confidence`
- `ic_confidence = sum(dim_score × dim_ic_weight) / sum(dim_ic_weight)`（IC 加权的得分置信度）
- `final_confidence = base_confidence × 0.6 + ic_confidence × 0.4`（权重走配置）

**3.5 _score_theme 返回值扩展**
- 原 `(score, verdict, capital_signal, volume_signal)`
- 改为 `(score, verdict, capital_signal, volume_signal, dim_scores_json, ic_confidence)`
- 调用方需同步更新

### 新增配置
```
opportunity.weight.dim_news = 1.0
opportunity.weight.dim_policy = 1.0
... (14 个维度)
opportunity.ic.enabled = false  # 默认关闭，需积累足够样本后开启
opportunity.ic.min_samples = 30  # 最少样本数
opportunity.ic.window_days = 90
opportunity.ic.refresh_interval_runs = 10  # 每 10 次回测刷新一次 IC
opportunity.confidence.ic_weight = 0.4  # IC 置信度融合权重
```

### 不做
- 贝叶斯置信度：需先验分布假设，工作量大，留 P2
- 信号衰减函数：需时间序列建模，留 P2

## 任务 4: S5 真实约束建模

### 现状

- `add_shares = (add_amount - calc_buy_fee(add_amount, fund_code)[0]) / current_price`

**4.2 per-fund 费率覆盖**（`fee_calculator.calc_buy_fee`）

**4.3 最小申购额约束**（`smart_add_planner._generate_single_plan`）

**4.4 份额取整**（`position_sizing.py`）

**4.5 止盈档位扣赎回费**（`exit_loop.build_exit_plan`）

## 风险与回滚

| 风险 | 缓解 |
|------|------|
| IC 计算样本不足导致权重波动 | `opportunity.ic.min_samples=30` + 默认关闭 |
| 回测扣成本后命中率大幅下降 | `fee_mode=relaxed` 选项 + `hit_threshold` 可调 |
| goal_aware 误拒补仓 | 默认 false，用户显式开启 |
| regime 主题分类错误 | `theme_category` JSON 可配，初期手动校准 |
| fund_metadata 费率填充率低 | 回退到全局 `fee.buy_rate`，不阻塞流程 |

**回滚**：所有改动走配置开关，默认 false（除 regime 阈值配置化、回测表扩展、摊薄成本扣费这三项无开关的改动，但都是向后兼容的增量）。
