## 实测设计

- 使用本地正在运行的服务 `http://127.0.0.1:8000`，采用数据库中的原始 Prompt 和当前配置模型。
- 每次最多运行两个分析，记录 HTTP 状态、任务 ID、最终状态、来源记录和实际模型 token。

- 所有任务完成前不改 Python 文件，避免 uvicorn 自动重载中断本轮运行。

## 已确认的问题与最小修复

市场情报的 `_fetch_hot_topics()` 把 `data` 一律视为字典，但实际盈米接口返回 `{"success": true, "data": []}`。有数据时也可能返回列表，现有代码会捕获 AttributeError 后丢弃话题。

选择兼容现有三种格式：`data.items`、`data` 列表、顶层列表。逐个解析文本块，跳过无法解析的块和非字典条目，保留其余有效话题与现有最多 8 条限制。相比改动所有 MCP 调用方，此方案只修复已复现的入口；不改模型、Prompt 或业务建议。

交易复盘首轮实测直接返回 HTTP 500：快照中 `pe_percentile: null` 进入求和。修复在读取快照时仅接纳有限且位于 0–100 的数值，兼容数字字符串和百分号。空快照、坏 JSON、非对象和无效分位保留交易明细，排除在 PE 均值及高低估比例的分母之外，明确输出有效样本覆盖率和缺失数量；不再默认填 50%。

全景诊断首轮任务虽然成功，正文却在表格行中间结束，且模型 completion 用满 6000 token。补充有界续写：仅当 `finish_reason=length` 时，在原对话上追加带 `reasoning_content` 的 assistant 内容和续写指令；最多追加两轮，累计所有真实 token。仅推理耗尽额度时同样续写，正常结束却没有正文、或多次续写仍截断时抛错，不能保存为成功。先只接入已发现问题的全景诊断入口，不改变其数据库 Prompt、模型或配置上限。

首轮还遇到本机 1082 代理停止监听：债券、指数出现连接错误，后续本地请求也无法发出。新的进程探针证实直连可达；代码变更后的服务重载重建模型客户端，失败项重新测试。不永久修改代理配置，也不绕过用户的模型配置。
