# 亏损持仓低估补仓回本联动设计稿

> 日期：2026-07-30
> 触发：用户要求补强"亏损严重持仓必须在低估时补仓才能回本"在预警/机会雷达/回本路径三处的缺失
> 范围：`backend/services/advisor/alert_scanner.py` + `opportunity_engine.py` + `smart_add_planner.py` + 前端展示
> 原则：所有新功能默认开关控制，不影响现有逻辑

---

## 一、背景

### 1.1 问题诊断

智能补仓（smart_add_planner）已深度体现"亏损严重+低估补仓回本"逻辑（信号A金字塔补仓、估值暂停、止损估值前置、L4修复时间、L5胜率），但三个用户感知入口存在缺失：

| 功能 | 现状 | 缺失 |
|------|------|------|
| **预警系统** | `loss_warning`(亏损<-15%) 和 `valuation_low`(分位<15%) 两个独立扫描，不交叉 | 无"亏损+低估"联合预警，深套+低估标的无专门提示 |
| **机会雷达** | 基于"新闻+主题规则"驱动，`_score_theme`维度5"持仓重叠风险"仅看`already_have`不看`profit_rate` | 与持仓盈亏完全脱钩，深套标的低估时无主动提示 |
| **回本路径** | 摊薄效果/修复时间/胜率分散在plan各字段 | 无结构化"补仓回本路径"输出，前端需自行拼接 |

### 1.2 用户价值

- **预警联合**：用户看到"白酒亏损-26%+估值分位3%→补仓窗口开启"比单独看到"亏损-26%"或"估值3%"更有决策价值
- **机会雷达感知持仓**：深套标的低估时主动推"补仓机会卡"，而非只推未持有的新主题
- **回本路径结构化**：一键看到"补W元→成本降至X→历史Y月回本→胜率Z%"

---

## 二、设计原则

1. **开关控制**：新增3个开关，默认开启（预警类项目规范要求默认开启）
2. **复用现有数据**：不新建表，复用 `portfolio_holdings`/`index_valuations`/`fund_nav_history`/`agent_runs`
3. **不破坏现有逻辑**：新增函数+条件分支，不修改既有扫描/评分函数的核心流程
4. **成本可控**：预警和机会雷达新增扫描复用已有持仓+估值缓存，不触发额外LLM调用

## 三、Phase 1：预警系统新增"亏损+低估"联合预警

### 3.1 新增开关

```python
# db/config.py 默认配置
"alerts.loss_plus_undervalued_enabled": True,  # 亏损+低估联合预警，默认开启
"alerts.loss_plus_undervalued_loss_threshold": -15,  # 亏损阈值（%），默认-15%
"alerts.loss_plus_undervalued_valuation_threshold": 30,  # 低估阈值（分位%），默认30%
```

### 3.2 新增函数 `scan_loss_plus_undervalued`

**位置**：`alert_scanner.py`，在 `scan_valuation_thresholds` 之后新增独立扫描函数

**逻辑**：
```
def scan_loss_plus_undervalued():
    1. 读取开关 alerts.loss_plus_undervalued_enabled，关闭则返回[]
    2. list_holdings() 获取所有持仓
    3. 对每个持仓:
       a. 读取 profit_rate，若 profit_rate > loss_threshold(-15%) 则跳过
       b. 读取 index_code，查 get_best_valuation(index_code, enable_online=True)
       c. 若 valuation.percentile < valuation_threshold(30%) → 命中
       d. 构建 alert:
          - alert_type: "loss_plus_undervalued"
          - severity: "info"（补仓机会，非风险）
          - title: f"{fund_name} 亏损{abs(profit_rate):.1f}%+估值分位{percentile:.1f}%，补仓窗口开启"
          - content: 包含 亏损幅度/估值分位/对应指数/当前持仓占比/建议操作
          - related_fund_code: fund_code
          - related_index_code: index_code
    4. 去重：24h内同 fund_code + alert_type 只保留1条
    5. 写入 portfolio_alerts 表
```

**severity 为 info 的理由**：这是"补仓机会"提示而非"风险预警"，与 `valuation_low` 一致用 info 级。

### 3.3 调用点

在 `app.py` 的定时扫描任务中，`scan_portfolio_risk` 和 `scan_valuation_thresholds` 之后调用 `scan_loss_plus_undervalued`。三者顺序：亏损预警 → 低估预警 → **亏损+低估联合预警**（去重：联合预警命中时抑制同标的的 `loss_warning` 重复）。

### 3.4 `_auto_candidate` 修复

当前 `_auto_candidate` 中 `loss_warning→add` 不检查估值就建议加仓，修复为：
- `loss_warning` 命中时，若对应指数估值分位 > 60% → 降级为 `watch`（观察，不加仓）
- `loss_warning` 命中时，若对应指数估值分位 < 30% → 升级为 `loss_plus_undervalued` 类型
- 无估值数据 → 保持 `watch`（保守）

## 四、Phase 2：机会雷达评分增加持仓盈亏维度

### 4.1 新增开关

```python
"opportunity.holding_loss_aware_enabled": True,  # 机会雷达感知持仓盈亏，默认开启
```

### 4.2 `_score_theme` 维度5增强

**位置**：`opportunity_engine.py` `_score_theme` 函数，维度5"持仓重叠风险"

**当前逻辑**（L698-838）：
- `already_have=True` → -15分（重叠风险）
- `already_have=False` → +8分（新主题）

**增强逻辑**：
```
if already_have:
    查询持仓中该主题相关基金的 profit_rate 和对应指数估值分位
    if profit_rate < -15% and valuation_percentile < 30%:
        # 深套+低估 → 补仓窗口，加分
        score = +12  # 反转为正分
        tag = "深套低估补仓窗口"
    elif profit_rate < -15% and valuation_percentile > 60%:
        # 深套+高估 → 减分，不补
        score = -20
        tag = "深套高估勿补"
    else:
        score = -15  # 原逻辑
        tag = "持仓重叠"
else:
    score = +8  # 新主题，原逻辑
```

### 4.3 新增"补仓机会"主题卡片类型

当维度5命中"深套低估补仓窗口"时，在 `opportunity` 卡片中：
- `opportunity_type`: 新增枚举值 `"loss_recovery"`（补仓回本型）
- 卡片标题前缀：`[补仓窗口]` 而非默认的 `[主题机会]`
- 卡片内容包含：当前亏损幅度、估值分位、建议补仓金额（复用 smart_add_planner 的金字塔档位计算）
- `entry_amount` 字段：复用 `_calc_entry_amount` 但叠加亏损档位加权

### 4.4 新增扫描函数 `_scan_holdings_loss_recovery`

**位置**：`opportunity_engine.py`，在 `scan_daily_opportunities` 中新增独立扫描分支

**逻辑**：
```
def _scan_holdings_loss_recovery():
    1. 读取开关 opportunity.holding_loss_aware_enabled
    2. list_holdings() 获取持仓
    3. 筛选 profit_rate < -15% 的深套标的
    4. 对每个深套标的查对应指数估值分位
    5. 若分位 < 30% → 生成 opportunity 卡片:
       - theme: f"补仓窗口-{fund_name}"
       - opportunity_type: "loss_recovery"
       - score: 基于亏损深度+低估程度计算（-30%亏损+3%分位 → 高分）
       - related_holdings: 含 fund_code/fund_name/profit_rate/valuation_percentile
    6. 与新闻驱动的机会卡合并去重（同 fund_code 只保留评分最高的）
```

## 五、Phase 3：智能补仓新增结构化"回本路径"输出

### 5.1 新增 `recovery_path` 字段

**位置**：`smart_add_planner.py` `_generate_single_plan` 函数，在 plan 输出末尾新增聚合字段

**字段结构**：
```python
plan["recovery_path"] = {
    "current_state": {
        "profit_rate": profit_rate,              # 当前盈亏率
        "loss_amount": profit_loss,              # 亏损金额
        "avg_cost": cost_price,                  # 当前平均成本
        "current_price": current_price,          # 当前价格
    },
    "valuation_context": {
        "index_name": index_name,                # 对应指数
        "percentile": percentile,                # 估值分位
        "level": "低估/适中/高估",               # 估值等级
        "zscore": zscore,                        # z-score
    },
    "add_scenario": {
        "suggested_amount": total_release,       # 建议补仓金额
        "new_avg_cost": avg_cost_after,          # 补仓后平均成本
        "cost_reduction": cost_price - avg_cost_after,  # 成本下降幅度
        "improvement_pct": improvement,          # 盈亏率改善
    },
    "recovery_estimate": {
        "median_recovery_months": median_months, # 历史中位修复月数
        "win_rate_12m": win_rate_12m,            # 12月正收益概率
        "win_rate_24m": win_rate_24m,            # 24月正收益概率
        "data_source": "index_price_history",    # 数据来源
    },
    "summary": f"当前亏损{abs(profit_rate)*100:.1f}%，估值分位{percentile:.1f}%处于低估区。"
               f"建议补仓{total_release:.0f}元，补仓后平均成本从{cost_price:.4f}降至{avg_cost_after:.4f}，"
               f"盈亏率改善{improvement:.1f}%。历史同分位回撤中位修复时间{median_months}个月，"
               f"12月正收益概率{win_rate_12m*100:.0f}%。",
}
```

### 5.2 触发条件

仅在以下条件同时满足时生成 `recovery_path`：
1. `profit_rate < -10%`（亏损标的）
2. 估值分位 < 60%（非高估）
3. 触发了信号A（金字塔补仓）或信号C（大跌定投）

非亏损标的或高估标的不生成 `recovery_path`（返回 `None`）。

## 六、去重与抑制规则

### 6.1 预警去重

| alert_type | 去重 key | 窗口 |
|------------|---------|------|
| `loss_plus_undervalued` | fund_code + alert_type | 24h |

### 6.2 预警抑制

- `loss_plus_undervalued` 命中时，24h内抑制同 fund_code 的 `loss_warning`（避免重复打扰）
- `valuation_low` 已有的指数级预警保留，不抑制（一个是标的级，一个是指数级）

### 6.3 机会雷达去重

- `_scan_holdings_loss_recovery` 生成的卡片与新闻驱动卡片按 `fund_code` 去重，保留评分高的
- 同 fund_code 24h 内只生成1张 `loss_recovery` 卡片

## 十、风险与边界

1. **估值数据缺失**：持仓无对应指数或指数无估值数据时，预警和机会雷达保守不触发（与 smart_add_planner 一致）
2. **债券基金**：债券基金无指数估值，`loss_plus_undervalued` 不触发（债券回本逻辑与权益不同）
3. **LLM 成本**：三个 Phase 均不触发额外 LLM 调用，纯规则+数据查询
4. **性能**：预警扫描复用持仓+估值缓存，单次扫描 < 2s；机会雷达新增扫描遍历持仓约 20 只，< 1s
