# 三模块联动优化方案：多智能体对话 × 机会雷达 × 智能补仓

> 日期：2026-08-01
> 目标：通过 Agent 架构优化对话中枢，用金融知识增强机会雷达与智能补仓，并打通三者联动，辅助更科学的投资决策。
> 范围：`backend/agent/`、`backend/services/advisor/opportunity_engine.py`、`backend/services/advisor/smart_add_planner.py` 及其关联模块。

> ⚠️ **金融严谨性声明**：本方案涉及投资逻辑，所有阈值/公式/策略参数**必须走数据库配置**（遵循 CLAUDE.md「金融严谨性」），不得硬编码。系统输出仅为投研辅助信息，**不构成投资建议，不承诺任何收益**，所有展示数据须标注来源与更新时间，涉及操作建议处须附带风险提示。投资有风险，决策需谨慎。

## 一、背景与目标

当前系统已建成三大核心模块，**各自工程完成度都很高**，但存在一个共性问题：**三者彼此割裂，且都是「规则引擎强、推理层弱」**。

用户的诉求可拆解为三件事：

1. **用 Agent 优化对话架构** —— 让多智能体真正成为「决策中枢」，而非只是播报员。
2. **用金融知识增强机会雷达** —— 让机会发现更科学（信号置信度、宏观联动、含成本回测）。
3. **用金融知识增强智能补仓** —— 让仓位管理更严谨（组合风险、止盈闭环、真实约束）。

最终目的：**三模块协同，在投资路上做出更好的决策**。

## 二、三模块现状全景

### 2.1 多智能体对话（最成熟，但有结构性负担）

**实际架构远超 CLAUDE.md 描述**，是「双引擎 + 11 专家 + 黑板通信 + 质量闭环」的真多智能体系统：

| 能力 | 现状 | 关键位置 |
|------|------|----------|
| 双引擎 | 六阶段 Pipeline（默认开）+ ReAct（降级） | `agent/core/pipeline.py`、`agent/core/orchestrator.py:5919` |
| 11 专家 | 数据库配置、工具隔离、动态加载 | `db/agents.py:418`、`agent/core/multi_agent.py:493` |
| ~50 工具 | 估值/行情/持仓/基金穿透/债券宏观/RAG | `tools/__init__.py` |
| 质量闭环 | 澄清→路由→执行→反思→交叉审阅→Bull/Bear辩论→仲裁→记忆 | `pipeline.py`、`orchestrator.py` |
| 工程化 | token 预算、成本分级、工具缓存去重、断线重连、prompt 版本管理 | `llm_service.py`、`rag.py` |

**主要短板**：
- 🔴 **god-file 危机**：`orchestrator.py` 7086 行、`pipeline.py` 150KB，双引擎逻辑（综合/仲裁/交叉审阅）大量重复。
- 🔴 **弱规划**：只会「选专家 + 排序」，无真正的任务分解 DAG 与动态 replan。
- 🟡 **评测闭环装了但默认关闭**：线上质量无持续度量，`specialist_weight` 自适应降权因缺评测输入难以生效。
- 🟡 **黑板是「只读共享」而非协商**；专家内部工具调用仍串行。
- 🟡 **大量硬编码 prompt 补丁**纠偏（`multi_agent.py` 顶部约束常量），非评测驱动。

### 2.2 机会雷达（新闻驱动的规则引擎，有回测闭环）

> 注：代码中有两套「机会雷达」。导航里的「机会雷达」指 **事件雷达 B**（`event_radar.py`，LLM 前瞻事件扫描）；本方案聚焦真正生成机会卡的 **主题机会引擎 A**（`opportunity_engine.py`，2917 行）。

**核心逻辑**：`scan_daily_opportunities`（`opportunity_engine.py:2656`）—— 遍历主题规则 → 关键词匹配新闻 → **无命中则跳过（:2677）** → 14 维加权评分 + 估值一票否决 → 入库 + 建 15 日回测 → 合并补仓机会卡 → 按分排序。

- **14 维评分**：新闻/政策/估值百分位/持仓重叠/技术指标/资金流向/情绪/领先指标/成交量/研报/两融/ETF 申赎等（`_score_theme:1118`）。
- **回测闭环（亮点）**：15 日超额收益 vs 沪深300，命中率反哺 —— 连续 3 次 miss 主题权重 ×0.8（`_apply_hit_rate_feedback:1875`）。
- **LLM 增强默认关闭**：L1 政策解读、L2 深度评审均默认 false，生产形态是**纯规则引擎**。

**主要短板**：
- 🔴 **新闻单驱动**：无新闻命中就不出卡，**纯低估无法独立触发机会**（除补仓卡）。
- 🔴 **核心阈值硬编码**：`_get_theme_thresholds:1033`（can_buy=75/82/78、否决分位 80/60/70）、14 维权重全部写死 —— **违反 CLAUDE.md 金融严谨性**。
- 🟡 **信号无置信度**：14 维等权求和，非 IC/概率加权；规则路径不输出 confidence。
- 🟡 **无宏观/行业联动**：regime 仅用沪深300 PE 百分位粗分。
- 🟡 **代理数据噪声**：研报用 `stock_comment_em` 凑数、两融用全市场深市代理主题级。
- 🟡 **回测初级**：不扣交易成本/滑点，无最大回撤/夏普/路径分析。
- 🟡 **止盈止损停留在文案**：`exit_plan` 无自动盯盘与触发提醒。

### 2.3 智能补仓（工程完成度最高的规则引擎）

**双引擎**：旧 4% 定投法（`db/portfolio.py:130`，硬编码）+ 新 **smart_add 计划器**（`smart_add_planner.py`，2166 行，主力）。

**核心逻辑**：`generate_smart_add_plan:942` 多信号并联 ——
- **引擎1** 估值 z-score 加权定投（`_calc_valuation_multiplier:157`）
- **引擎2** 金字塔补仓（`_calc_pyramid_tiers:187`，5 档 -10%~-50%）
- **信号 A-F**：金字塔/趋势加仓/大跌定投/价值平均VA/网格/退出信号
- **六维仓位约束**（`position_sizing.py:583`）：目标仓位锚定 + 穿透集中度 + 首次建仓 + 收益弹性 + 动态减仓 + 资金约束
- **增强指标**：基金分类、半凯利上限、回撤修复时间、估值胜率（`smart_add_metrics.py`）

**主要短板**：
- 🔴 **无相关性/组合风险建模**：穿透集中度只看「同一指数」，**不计算持仓间相关系数/协方差** —— 补仓可能把高相关持仓越补越集中（真实金融风险盲区）。
- 🔴 **补仓后无止盈闭环**：退出信号 F 默认关闭，无「补仓→回本目标→到点提醒」状态机。
- 🟡 **纯规则、无 LLM 推理**：三个核心文件零 LLM 调用，LLM 只在消费侧播报。
- 🟡 **资金规划静态**：资金池 = 总资产×15% 固定比例，无目标导向（goal-based）。
- 🟡 **历史模拟单边下跌假设**：无蒙特卡洛/真实路径回测。
- 🟡 **真实约束缺失**：摊薄成本不含申购费，无最小申购额/份额取整。

## 三、核心诊断：三模块的「联动断点」

三模块各自强大，但**没有形成决策闭环**。当前的数据流是**单向、割裂**的：

```
机会雷达(opportunity_engine)  ──┐
                                ├─→ [仅作为上下文文本注入] ─→ 对话Agent ─→ 自然语言播报
智能补仓(smart_add_planner)   ──┘         (conversation_context)
        ↑
   各自独立定时/请求触发，互不感知
```

**四个关键断点**：

1. **雷达 ↔ 补仓 不通信**：雷达发现「某主题低估可买」，不会触发补仓引擎去算「该买多少、怎么分批」；补仓引擎的「深套补仓卡」与雷达的「loss_recovery 卡」各算一套，逻辑重复。
2. **Agent 只在消费侧**：Agent 通过 `query_smart_add_plan`/`query_valuation` 拿规则引擎的结果再播报，**没有真正驱动「发现→评估→ sizing→风控→跟踪」的决策流水线**。
3. **风控视角缺失**：雷达排序只看 score、补仓只看单标的，**都没有组合层的相关性/风险预算视角**，三者叠加可能导致过度集中。
4. **无统一跟踪闭环**：雷达有 15 日回测、补仓有反事实验证，但**两套验证各自为政**，没有「这笔决策最终赚/亏了多少、归因到哪个信号」的统一账本。

> **核心论点**：优化的最大杠杆不是把单个模块做得更复杂，而是**让 Agent 成为串联三者的「投研决策流水线」**，同时用金融知识把两个规则引擎的「科学性」补齐。

## 四、总体架构设计：Agent 作为「投研决策中枢」

### 4.1 目标数据流（To-Be）

```
                    ┌─────────────────────────────────────────────┐
                    │          多智能体决策流水线 (Pipeline)          │
                    │                                               │
  ① 发现层          │   ② 评估层          ③ 执行层        ④ 风控层    │
 ┌──────────┐      │  ┌──────────┐     ┌──────────┐    ┌─────────┐ │
 │ 机会雷达  │─────→│  │ 专家辩论  │────→│ 智能补仓  │───→│组合风险  │ │
 │(估值/宏观 │信号卡 │  │ 估值+宏观 │sizing│ 金字塔/凯利│    │相关性矩阵│ │
 │ 驱动通道) │      │  │ +行为金融 │     │ +VA/网格  │    │风险预算  │ │
 └──────────┘      │  └──────────┘     └──────────┘    └─────────┘ │
      ↑            │        │                │              │       │
      │            │        └───────┬────────┴──────────────┘       │
      │            │                ↓                                │
      │            │        ⑤ 决策卡片(含来源/置信度/风险提示)         │
      │            └────────────────┬───────────────────────────────┘
      │                             ↓
      │                    ⑥ 统一跟踪账本 (决策→执行→回测→归因)
      └─────────────── 命中率/IC 反哺 ──┴──→ 信号权重自适应 + 专家权重自适应
```

**三个角色的明确分工**：

| 模块 | 决策链路角色 | 回答的问题 |
|------|--------------|------------|
| **机会雷达** | 发现层 | **What & When** —— 现在有什么机会、贵不贵、时机如何 |
| **多智能体** | 评估 + 编排层 | **Why & Whether** —— 为什么是机会、要不要做、逻辑是否成立（推理） |
| **智能补仓** | 执行层 | **How much & How** —— 买多少、怎么分批、何时退出 |
| **组合风控（新增/强化）** | 贯穿风控层 | **How risky** —— 叠加后组合是否过度集中、是否超风险预算 |

### 4.2 关键设计原则

1. **规则引擎负责「算」，Agent 负责「判」**：可量化的（估值分位、凯利比例、回测收益）交给确定性规则；需要综合、推理、解释的（行业逻辑是否反转、政策实质影响、多信号冲突取舍）交给 Agent。
2. **一切金融参数配置化**：新增/存量的阈值、权重、公式系数全部进 `system_config`，满足 CLAUDE.md，并支持按 regime 动态调整。
3. **每个信号输出置信度与来源**：不再只给一个 score，而是给「score + confidence + evidence[] + data_source + update_time」。
4. **闭环驱动进化**：统一跟踪账本的回测结果，同时反哺「信号权重」（雷达）和「专家权重」（Agent），让系统越用越准。

## 六、三模块联动的典型场景

**场景：用户问「最近有什么值得加仓的机会？」**

| 阶段 | 当前（As-Is） | 目标（To-Be） |
|------|--------------|---------------|
| ① 发现 | Agent 调 `query_valuation` 零散查估值 | 决策流水线先拉**机会雷达今日信号卡**（含估值驱动通道的新增低估机会） |
| ② 评估 | 单专家直接播报 | **估值专家 + 宏观专家 + 行为金融专家辩论**：宏观判断 regime 是否支持、行为金融提示「是否因亏损而想加仓」的偏差 |
| ③ sizing | 调 `query_smart_add_plan` 拿单标的金额 | 补仓引擎给出金字塔/凯利档位，**叠加相关性降权**后的建议金额 |
| ④ 风控 | 无 | **组合风险层**检查：加仓后是否突破行业/指数集中度上限、是否超风险预算，给出否决或降档 |
| ⑤ 输出 | 自然语言回复 | **决策卡片**：结论 + 置信度 + 分批计划 + 止盈止损 + 数据来源/更新时间 + 风险提示 |
| ⑥ 跟踪 | 无统一账本 | 用户确认后写入**统一跟踪账本**，15/30 日自动回测，归因到信号，反哺权重 |

## 九、金融严谨性与风险提示（强制）

- 本方案所有新增/修改的**估值阈值、信号权重、凯利系数、止盈止损比例、仓位上限**必须存 `system_config` 或 `analysis_agents` 表，**严禁硬编码**。
- 所有展示给用户的金融数据必须标注**数据来源 + 更新时间**；代理/近似数据（研报、两融、北向）须明确标注质量等级。
- 涉及操作建议（买入/加仓/减仓/止盈）的输出必须附带**风险提示**，不得给出绝对化收益承诺或「保本」「必涨」等表述。
- 凯利公式、相关性矩阵等对估计误差敏感，须用**分数凯利/收缩估计**等鲁棒方法，并在 UI 提示「模型结果依赖历史估计，存在误差」。
- LLM 输出须做 sanitization 防 prompt 注入（遵循质量门禁）。

## 十一、一句话总结

三大模块**单兵作战能力都很强，但缺一个「司令部」**。本方案的核心是：**让多智能体从「播报员」升级为「投研决策流水线」的编排中枢**，用金融知识把机会雷达（信号科学化 + 估值驱动 + 含成本回测）和智能补仓（组合风险 + 止盈闭环 + 真实约束）的科学性补齐，再用**统一跟踪账本**把「发现→评估→执行→风控→回测→进化」串成闭环 —— 最终让系统越用越聪明，辅助更理性、更可持续的投资决策。

> 再次提醒：本系统为投研辅助工具，所有输出不构成投资建议，投资有风险，入市需谨慎。
