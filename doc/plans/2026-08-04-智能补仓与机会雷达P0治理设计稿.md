# 智能补仓与机会雷达 P0 治理设计稿

> 日期：2026-08-04  
> 范围：智能补仓金额安全、估值百分位口径、机会雷达回测标签与统计可信度  
> 目标：先消除可能放大真实投资风险的基础缺陷，再进入策略优化阶段

## 一、背景与现状

当前两个功能已经形成较完整的产品链路：

- 智能补仓包含估值加权定投、金字塔、趋势、大跌、价值平均、网格、退出信号、仓位规模和反事实记录。
- 机会雷达包含新闻、政策、估值、技术、资金、情绪、量能、研报、融资、ETF 流量、宏观状态等维度，并有冷却、回测和权重反馈。

但本地生产数据暴露出三个基础问题：

1. `smart_add_plans` 中 157 条有估值分位的记录，有 98 条位于 `(0, 1)`，说明 `0-1` 比例制与 `0-100` 百分制仍在链路中混用。
2. 13 天生成 280 份智能补仓计划，累计 `final_suggested_amount` 约 545 万元；部分标的的最终金额约 5 万元，而触发信号合计只有数百至数千元。
3. 机会雷达 81 条回测中 57 条已复盘，命中率 31.6%；只有 6 条带维度快照，且所有回测的 `signal_source` 都是 `news`，暂不具备自动学习 15 维权重的统计基础。

因此，本阶段不增加新策略维度，优先治理数据口径、预算边界和评估口径。

## 二、方案选择

### 方案 A：只修百分位和明显条件判断

优点是改动小；缺点是逐基金独立生成目标仓位的结构仍会放大总预算，不能从根本上约束建议金额。

### 方案 B：组合预算治理 + 百分位统一 + 回测标签治理（采用）

先统一数据口径，再把补仓建议纳入组合级月度预算分配；机会雷达只修复回测来源和统计可信度，不改现有 15 维评分公式。该方案能直接降低错误建议影响，且可以通过既有历史表验证。

### 方案 C：重写为完整资产配置优化器

长期方向更完整，但需要目标资产配置、家庭现金流、投资期限等数据全部可靠。当前 `smart_add.goal_aware_enabled=false`，直接重写会扩大范围并引入未经验证的新假设，本阶段不采用。

## 三、设计原则

1. **组合预算先于单标的信号**：所有基金共享同一个本期可投资预算。
2. **缺数据时收紧，不放宽**：现金余量为零、估值无效、价格过期时不得回退为高仓位上限。
3. **信号决定节奏，不创造资金**：信号金额与目标缺口都只是需求，最终金额必须同时满足现金和组合约束。
4. **建议与执行分离**：计划可以保留被截断前的需求，但决策候选和假设交易只使用截断后的金额。
5. **评估按策略来源拆分**：新闻、估值、补仓回本等不同策略不能混为同一类样本。
6. **向后兼容**：保留现有 API 字段，只新增解释字段；数据库历史记录通过迁移修正。

## 四、P0-1 估值百分位统一

### 4.1 统一契约

所有业务层使用 `0-100` 百分制：

```text
None / 空值       -> None
0 <= x <= 1       -> x * 100
1 < x <= 100      -> x
x < 0             -> 0
x > 100           -> 100
无法解析           -> None
```

`0` 和 `1` 存在歧义。为避免把 `1%` 误当作 `100%`：

- 数字 `0` 保持 `0`。
- 数字 `1` 保持 `1`，只有 `0 < x < 1` 才按比例制转换。
- 上游明确标识为比例制的数据，在保存前由数据源适配器乘以 100。

### 4.2 实施位置

- `backend/db/valuations.py`
  - `_normalize_percentile()` 作为唯一通用入口。
  - `get_best_valuation()` 返回前再次执行标准化，覆盖在线兜底和历史旁路。
- `backend/services/advisor/smart_add_planner.py`
  - 单标的计划入口增加防御性标准化，避免旧数据污染金额。
- 数据迁移
  - 仅修正明确满足 `0 < percentile < 1` 的 `index_valuations`、`smart_add_plans` 历史数据。
  - 不修改恰好为 `0` 或 `1` 的记录。

### 4.3 异常保护

计划生成时若分位不是 `None` 且不在 `[0, 100]`，将估值视为不可用并添加 `data_warning`，不得生成估值增强金额。

## 五、P0-2 组合级补仓预算

### 5.1 单标的需求

每个标的先计算两类需求，不立即作为最终金额：

```text
signal_demand = 所有已触发买入信号金额合计
target_demand = max(0, 目标仓位缺口 / 调整月数)
raw_demand = max(signal_demand, target_demand)
```

保留 `max()` 是为了兼容既有目标仓位模型，但它只能生成需求，不能直接成为最终建议。

### 5.2 组合可用预算

```text
cash_budget = max(0, 可用现金 + 本月可投入现金流)
pool_budget = max(0, 总资产 * pool_pct - 本周期已使用资金池)
monthly_budget = min(cash_budget, pool_budget)
```

约束说明：

- 不再使用未来 3 个月现金流作为“本次可投入金额”。
- 现金与月度结余均为零时，组合预算必须为零。
- 应急金、目标桶等高级约束仍由现有 goal-aware 模块处理，未开启时也必须保留基础现金约束。

### 5.3 预算分配

使用确定性、可解释的比例缩放：

```text
total_demand = sum(raw_demand_i)
scale = min(1, monthly_budget / total_demand)
allocated_i = raw_demand_i * scale
```

分配后再次执行单标的硬上限：

```text
final_i = min(
  allocated_i,
  单标的目标仓位剩余空间,
  单标的配置硬上限剩余空间,
  当前持仓市值 * max_add_vs_position_mult
)
```

退出信号、安全阀、基本面健康检查任一阻止买入时，`final_i=0`。

### 5.4 API 新增解释字段

组合层新增：

```json
{
  "monthly_budget": 10000,
  "total_raw_demand": 24000,
  "allocation_scale": 0.4167,
  "budget_basis": "cash_plus_monthly_inflow",
  "budget_exhausted": true
}
```

单计划新增：

```json
{
  "raw_suggested_amount": 5000,
  "final_suggested_amount": 2083.5,
  "budget_scale": 0.4167,
  "budget_note": "组合本月预算不足，按需求比例缩减"
}
```

原有 `total_suggested`、`target_driven_monthly` 等字段保持不变。

### 5.5 副作用顺序

组合分配完成后才能执行：

1. 保存 `smart_add_plans`。
2. 创建建议快照和假设交易。
3. 转换为决策候选。

任何副作用都只能读取 `final_suggested_amount`，不得继续读取金字塔原始金额或未截断需求。

## 六、P0-3 现金约束语义修复

当前目标仓位计算中，`cash_room_pct <= 0` 会回退到 `user_max_pct`。修改为：

```text
cash_room_pct is None -> 不使用现金约束（仅限确实无法取得现金数据）
cash_room_pct <= 0    -> 目标仓位增量约束为 0
cash_room_pct > 0     -> 使用现金允许的仓位增量
```

同时为现金读取结果增加 `data_available`，区分“现金确实为零”和“数据源不可用”。

## 七、P0-4 机会雷达回测来源与统计治理

### 7.1 来源契约

统一枚举：

```text
news              新闻与政策驱动
valuation         独立估值驱动
loss_recovery     持仓回本机会
manual            手工研究或历史导入
```

创建机会卡和回测记录时必须显式传递 `signal_source`，不再依赖数据库默认值 `news`。

### 7.2 回测统计分层

API 统计同时提供：

- 按 `signal_source`。
- 按 `theme`。
- 按 `verdict`。
- 已复盘数量、命中率、平均净收益、平均超额收益。
- `independent_sample_count`：同一主题在一个持有窗口内只计第一条信号。

默认总命中率使用独立样本口径；原始记录命中率作为 `raw_hit_rate` 保留。

### 7.3 学习开关门槛

`opportunity.ic.enabled` 保持关闭，满足以下条件后才允许开启：

- 至少 100 个独立已复盘样本。
- 每个参与学习的维度至少 30 个非空样本。
- 至少覆盖 3 个市场月份。
- 数据中至少存在 2 类 `signal_source`。

本阶段不自动修改评分权重。

## 八、暂不实施的内容

- 不新增第 16 个以上的机会评分维度。
- 不重写凯利公式，但将其从“可直接创造最终金额”降为目标仓位上限参考。
- 不启用自动交易。
- 不改变前端整体布局。
- 不在本阶段引入复杂优化器、机器学习模型或蒙特卡洛模拟。
- 不对历史机会卡重新生成 verdict，避免混淆历史规则和新规则。

## 九、测试设计

### 9.1 百分位

- `0.4274 -> 42.74`
- `0 -> 0`
- `1 -> 1`
- `34.83 -> 34.83`
- `"84.71%" -> 84.71`
- 非法字符串返回 `None`
- `get_best_valuation()` 的本地、在线和 PB 兜底路径均输出 `0-100`

### 9.2 现金与组合预算

- 现金为零、月度结余为零时，所有最终补仓金额为零。
- 总需求小于预算时不缩放。
- 总需求大于预算时按同一比例缩放，合计不超过预算。
- 被退出信号或安全阀阻止的标的不参与预算分配。
- 快照、假设交易和决策候选使用分配后的最终金额。
- 单标的最终金额不超过持仓市值倍数和目标仓位剩余空间。

### 9.3 机会回测

- 不同通道创建的回测记录保留正确 `signal_source`。
- 同主题持有窗口内多条记录只形成一个独立样本。
- 原始命中率与独立样本命中率同时返回。
- 样本不足时 IC 学习保持关闭并给出明确原因。

## 十、验收标准

1. 新生成计划中的非空估值百分位全部位于 `[0, 100]`，且比例制样本正确乘以 100。
2. 所有计划的 `sum(final_suggested_amount) <= monthly_budget`。
3. 无现金且无本月结余时，`sum(final_suggested_amount) == 0`。
4. 任一计划的最终金额不得超过其原始需求和所有单标的硬上限。
5. 智能补仓的快照、假设交易、持久化计划和决策候选金额一致。
6. 新增机会回测的 `signal_source` 不再全部为 `news`。
7. 机会统计能同时展示原始样本与独立样本结果。
8. 相关后端测试全部通过，原有 API 字段无破坏性变化。
