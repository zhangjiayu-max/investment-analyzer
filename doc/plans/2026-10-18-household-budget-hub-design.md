# 家庭预算中枢升级设计

## 背景与目标

当前家庭财务页面已经能够展示持仓资产、账户现金、周期账单和月度支出，但月收入入口隐藏在支出弹窗里，收入为空时多个指标只能显示不完整结果；全账户诊断主要关注投资组合评分，不能回答家庭最关心的三个问题：本月还可以花多少钱、未来几个月现金是否够用、扣除安全垫后还能投入多少资金。

本次升级采用家庭预算中枢方案，建立统一的数据链：

`月收入 → 固定必缴 → 浮动支出 → 本月可花 → 未来 3 个月现金安全线 → 可投资结余`

目标是让财务总览成为家庭现金决策入口，让全账户诊断输出有证据、可执行的行动清单。现有持仓、现金、账单和已支付历史记录不删除、不改写；未登记的数据明确显示缺口。

## 设计范围

### 1. 账本层

- 继续使用现有支出记录和周期账单。
- 月收入和月度全额支出预算保存在用户财务画像中，并提供财务总览顶部的直接编辑入口。
- 每月区分已记录实际支出、周期账单待支付、周期账单月均预留和未确认的日常支出。
- 用户可以明确标记某月“支出已记全”。标记后，不再用日常预算兜底，但待支付账单仍计入必要支出。

### 2. 计划层

现金流计算统一输出以下字段：

- `monthly_income`：用户填写的月收入；为空或为零时标记为未知，不用历史测试值代替。
- `fixed_obligation`：所选月份实际固定支出与待支付固定账单的必要负担。
- `known_expense`：该月已登记的实际支出。
- `budget_expense`：用户填写的全月支出预算。
- `safe_to_spend`：收入已知时，收入减固定必缴、已发生浮动支出和必要预留后的可花金额；收入未知时返回空值并说明缺少收入。
- `investable_surplus`：收入已知且月度数据可用时，扣除必要支出后的可投资结余；不把可花金额误称为可投资金额。
- `cash_runway_months`：账户现金扣除必要预留后，按必要月支出可覆盖的月数。
- `forecast_3m`：未来三个月按周期账单和月均必要支出计算的现金余额预测。

固定账单的月度、季度和年度频率继续按现有规则折算到目标月份。已经支付的账单保留支付快照，修改周期账单模板只影响未来待支付计划。

### 3. 资产负债层

- 投资资产口径继续复用持仓管理的“持仓市值 + 已登记账户现金”。
- 页面明确标注这是“已登记投资资产”，不把它称作完整家庭净资产。
- 负债分为“已登记余额”和“本月还款支出”。只有登记负债余额后才计算净资产和负债余额变化；只有月供时显示“余额未知”。
- 车贷、保险等固定支出按分类分开。保险不能进入贷款本金或负债余额计算。

### 4. 决策层

全账户诊断从泛化评分改为最多 5 条按优先级排序的行动清单，每条包含：问题、证据、影响、建议动作和缺失数据。规则包括：

1. 收入未录入：提示无法计算结余率、负债收入比和可投资结余，并提供直接填写入口。
2. 本月固定必缴待支付：展示账单名称、金额和截止状态。
3. 未来三个月现金安全线：现金覆盖不足时提示具体缺口月份和金额。
4. 月度支出未记全：说明预测仍使用预算兜底，避免把预测值当作实际值。
5. 负债余额未知：明确无法判断完整净资产和负债率，只展示月供压力。
6. 现金足够且超过安全垫：提示可评估投资，但不自动生成买入动作。
7. 投资配置偏离或压力测试风险较高：保留现有投资诊断动作，排在家庭现金安全问题之后。

投资组合健康分和四笔钱配置继续保留为第二层分析，不再作为家庭诊断的唯一结论。

## 页面结构

### 财务总览

顶部新增“本月家庭现金计划”主卡，按顺序展示：月收入、固定必缴、已发生支出、剩余可花、可投资结余。收入或预算为空时，主卡显示补充按钮和缺失原因，点击后可直接编辑并保存。

主卡下方展示三个月现金预测、固定账单状态、投资资产口径和负债余额状态。指标旁的说明使用不被卡片裁剪的浮层，长文本支持换行和视口内定位。

### 全账户诊断

首屏先显示“今天最需要处理的事情”，使用行动清单而不是单一健康分。每条行动可以跳转到收入设置、账单列表、月度支出或负债录入。投资评分、四笔钱和持仓详情放在后续区域。

### 资金桶

资金桶的当前金额继续与已登记投资资产同步，但新增“用途覆盖”提示：应急桶用必要月支出计算目标，长期桶不参与本月可花金额计算。已归档资金桶不进入当前目标汇总。

## 数据流与接口

财务总览继续通过 `/api/finance-dashboard?month=YYYY-MM` 获取聚合数据。后端在现金流聚合中统一生成上述字段，前端不重复推导关键金额。新增或扩展的字段保持向后兼容，缺失数据使用 `null` 和状态字段表达。

月收入和全月预算沿用 `/api/profile` 的读写接口，但财务总览直接调用并刷新仪表盘。全账户诊断沿用 `/api/health-v2/dashboard`，把家庭现金流诊断和投资诊断放在同一返回体中，并让缓存签名包含现金流、账单和画像版本。

## 错误处理与数据保护

- 收入、预算、账单金额必须为有限非负数；非法值由 API 返回可读错误。
- 现金流任一来源失败时，页面显示该模块不可用和重试入口，不使用旧缓存冒充最新数据。
- 未登记数据用“未知/待补充”显示，不用 0 代替。
- 不自动删除用户的真实支出、持仓、现金或账单。历史测试画像只有在用户明确确认后才允许清空；本设计不包含自动清理。
- 修改周期账单模板不得覆盖已支付历史快照。

## 验收与测试

后端测试覆盖：

- 月收入为空、有值、为零时的现金流字段和状态。
- 固定账单已支付、待支付、季度/年度折算和未来三个月预测。
- 修改账单模板不改变历史支付快照。
- 现金流变化会使财务总览和健康诊断缓存失效。
- 负债余额未知时不计算净资产，只展示月供压力。

前端测试覆盖：

- 顶部收入编辑可打开、保存、失败重试并刷新所有相关指标。
- `null` 指标显示原因和行动入口，不能显示为误导性的 0。
- 诊断行动按家庭现金安全优先排序。
- 浮层长文本在卡片边缘和窄屏下完整可见。
