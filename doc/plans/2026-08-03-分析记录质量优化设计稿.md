## 二、优化方案

### 2.1 diversification_ai 优化

#### 优化 1：prompt 瘦身（P0）

**位置**：[routers/analysis/diversification.py:417-418](file:///Users/xiaoyuer/projects/investment-analyzer/backend/routers/analysis/diversification.py#L417-418)

**现状**：
```python
## 📄 MCP 原始数据（供验证和深度参考）
{mcp_raw_block}
```
mcp_raw_block 包含：资产穿透原始JSON + 相关性原始JSON + 5只基金行业配置原始JSON + 组合诊断原始JSON + 市场行情 + 热点 + 3个行业新闻，约 4.5 万字符。

**优化**：删除 MCP 原始数据块，只保留预计算结果。预计算结果（第402-415行）已经包含：
- 基金集中度检验（带阈值标注）
- 相关性检验（带系数和风险等级）
- 行业集中度汇总（带阈值标注）
- 资产大类穿透
- 估值参考

这些预计算结果是结构化的、带阈值的，比原始 MCP JSON 更适合 LLM 使用。原始数据只在预计算解析失败时才注入（作为降级）。

**预期收益**：prompt 从 5.8 万 tokens 降到 1.2 万 tokens，成本降 80%。

#### 优化 2：增量分析（P1）

**位置**：[routers/analysis/diversification.py:195](file:///Users/xiaoyuer/projects/investment-analyzer/backend/routers/analysis/diversification.py#L195)

**现状**：每次全量分析，不参考历史结果。

**优化**：在 user_content 开头注入"上次分析结论"（取最近一条 diversification_ai 记录的 result_data 摘要），要求 LLM 对比变化：
```
## 上次分析结论（{date}）
{last_result_summary}

## 本次分析要求
请对比上次分析，重点说明：
1. 哪些风险已改善（如集中度下降、相关性降低）
2. 哪些风险新增或加剧
3. 本次新增的变化点（新持仓、新交易等）
4. 如果结论与上次相同，说明原因（如"组合未变化"）
```

**预期收益**：避免同质化，每次分析有增量价值。

#### 优化 3：异常数据识别（P2）

**位置**：[routers/analysis/diversification.py:209-217](file:///Users/xiaoyuer/projects/investment-analyzer/backend/routers/analysis/diversification.py#L209-217)

**现状**：直接用持仓数据，不校验异常。

**优化**：在预计算阶段加异常检测：
```python
# 异常数据检测
anomaly_lines = []
for h in holdings:
    profit_rate = h.get("profit_rate", 0) or 0
    if abs(profit_rate) > 1.0:  # 收益率绝对值 >100%
        anomaly_lines.append(
            f"- ⚠️ {h.get('fund_name','')}({h.get('fund_code','')}) "
            f"收益率 {profit_rate*100:.1f}% 异常，疑似成本数据错误，"
            f"本次分析排除该基金的成本/收益数据"
        )
```

在 user_content 的预计算分析区块加"### ⚠️ 数据异常警告"，让 LLM 知道哪些数据不可信。

**预期收益**：避免基于 bug 数据做分析。

### 2.2 deep_dive 优化

#### 优化 1：数据断层标注（P0）

**位置**：[routers/analysis/deep_dive.py:209-227](file:///Users/xiaoyuer/projects/investment-analyzer/backend/routers/analysis/deep_dive.py#L209-227)

**现状**：user_content 只列交易记录，不标注基准持仓覆盖率。

**优化**：在 user_content 的"交易记录"区块后加"数据断层提示"：
```python
# 计算交易记录覆盖率
total_shares = holding.get("shares", 0) or 0
tx_shares = sum(t.get("shares", 0) or 0 for t in txs if t.get("transaction_type") == "buy")
coverage = (tx_shares / total_shares * 100) if total_shares > 0 else 0

data_gap_section = ""
if holding.get("has_base_position") and coverage < 95:
    data_gap_section = f"""
## ⚠️ 数据断层提示
该持仓为基准导入（has_base_position=1），交易记录仅覆盖 {coverage:.1f}% 的份额。
剩余 {100-coverage:.1f}% 的份额为初始导入，无交易明细。
- 操作质量评估仅覆盖有记录的部分
- 年化收益计算仅基于有记录的份额，不代表整体持仓真实年化
- 底仓成本为基准导入值，可能存在偏差
"""
```

**预期收益**：LLM 不会对无记录份额做年化计算，避免误导。

#### 优化 2：风险维度增强（P2）

**位置**：[routers/analysis/deep_dive.py:49](file:///Users/xiaoyuer/projects/investment-analyzer/backend/routers/analysis/deep_dive.py#L49) 的 system_prompt（存 analysis_agents 表）

**现状**：system_prompt 侧重投资机会分析，缺风险维度。

**优化**：在 system_prompt 追加风险维度要求（通过 UPDATE analysis_agents）：
```
## 风险维度（必须覆盖）
1. 行业 Beta 风险：与大盘相关性，系统性风险暴露
2. 利率敏感性：对利率变化的反应（债券/银行板块尤其重要）
3. 基本面风险：行业特有风险（如银行坏账率、白酒库存、医药集采）
4. 集中度风险：单一持仓占比过高、单一行业暴露
5. 流动性风险：基金规模、赎回限制
```

**预期收益**：分析更全面，有风险对冲视角。

#### 优化 3：组合数据校验（P2）

**位置**：[routers/analysis/deep_dive.py:162-168](file:///Users/xiaoyuer/projects/investment-analyzer/backend/routers/analysis/deep_dive.py#L162-168)

**现状**：直接注入 build_portfolio_facts() 结果，不校验异常。

**优化**：在 facts_context 注入前加异常标注：
```python
# 组合数据异常检测
facts_anomaly = []
for h in holdings_all:  # build_portfolio_facts 内部的持仓
    profit_rate = h.get("profit_rate", 0) or 0
    if abs(profit_rate) > 1.0:
        facts_anomaly.append(f"{h['fund_name']} 收益率{profit_rate*100:.1f}% 异常")
if facts_anomaly:
    facts_context += f"\n\n⚠️ 组合数据异常警告：{', '.join(facts_anomaly)}，相关基金数据可能失真"
```

**预期收益**：避免基于 bug 数据做组合建议。
