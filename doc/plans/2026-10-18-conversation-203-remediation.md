# 对话203质量问题修复计划

**目标：** 将审查中确认的错误转为确定性校验，阻止错误动作、无效专家输出与不可靠证据进入决策链。

**方案：** 采用共享校验函数加现有调用点接入；保留当前 Pipeline 和数据库结构，避免整套编排重写。仅改提示词无法约束候选与指标，整体架构重写又超出本次根因范围。以原始工具、统一持仓快照和用户画像为事实来源，LLM 审查意见必须可被事实纠正。

**验证：** 先写复现测试，再实现；测试使用临时数据库和替代模型，禁止真实交易和外部模型调用。最后运行相关后端回归及独立代码审查。

## 执行清单

- [x] 专家输出：识别带ID工具标签，验证重试完整性，保留有效初稿；缺失关键分析触发降级或补救；收敛不能仅凭两份非空预览。
- [x] RAG：重排后质量门槛、相关性优先于画像加分、引用ID与原文保留、隔离明显公式错误证据。
- [x] 组合证据：总资产/KYC口径统一、交易后权重由程序计算、日期窗口说明；历史结论随持仓指纹失效。
- [x] 决策候选：移除全文关键词与首代码匹配，仅接收完成且校验过的标的级动作；对条件、冲突与未知结果保守处理。
- [x] 审查综合：向反思和最终合成传递工具证据，纠正工具缺失误报，校准统一置信度；标的级动作驱动守卫。
- [x] 持久化监控：补全专家结构字段、真实失败状态、独立专家数、有效检索覆盖和执行时间。
- [x] 回归审查：检查集成、运行相关测试、独立审查、更新此清单并提交已完成改动。

## 范围说明

本次不重写历史对话、不自动改动真实交易或用户KYC。已存在的错误候选提供可审查的纠正路径，避免静默修改用户业务记录。涉及基金久期、底层持仓、官方费率等外部缺失数据，系统应明确缺失并降低动作确定性。

## 运维与能力边界
