# 功能精简（减负）+ 重点功能深挖

日期：2026-10-15

## 背景

项目功能堆砌已失控，直接导致易用性差。体检结论：

| 维度 | 数量 |
|------|------|
| 前端页面 | 40 个（6 个导航组） |
| 后端路由 | ~146 条，散在 90+ 路由文件 |
| Agent 工具 | 52 个 |
| Agent 定义 | 17 条（agents 表）+ 12 条（analysis_agents 表）两套并存 |
| 核心文件 | orchestrator.py 7091 行 / EventRadarPage.vue 8638 行 / pipeline.py 3513 行 |

核心病灶：双编排引擎并存、概念重复（组合诊断拆 7 页）、大量后端-only 半成品、死代码与重复数据。

## 目标

1. **减负**：屏蔽低频/工程治理类功能，聚焦"提升理财能力"的核心功能。
2. **深挖两大核心**：AI 对话多智能体协同、市场雷达。

## 决策（用户拍板）

- 屏蔽力度：**导航折叠 + 配置开关**（可逆，不删代码）
- 「系统治理」14 个工程页：**整体隐藏**
- 深挖方向：AI 对话收敛双引擎 + 市场雷达拆分超载前端

## 已实施：阶段 1 减负

### 1.1 前端导航隐藏

**机制**：`navigation.js` 引入 `hidden` / `devOnly` 标记 + `localStorage.investment_dev_mode` 开发者模式开关。

**分级**：

| 等级 | 处理 | 页面 |
|------|------|------|
| 🟢 保留 | 不变 | dashboard / chat / event-radar / market-intelligence / bond / portfolio / smart-add / alert-center / decisions / decision-center / valuation / articles / goal-buckets / family-finance / health-v2 |
| 🟡 下沉 | `hidden: true` | attribution / behavior / accuracy / allocation-dashboard / strategy-sandbox / gallery / knowledge / author / linked / health / feature-usage |
| 🔴 治理组 | `devOnly: true`（分组级） | group-system 下全部：admin-agents / analysis-log / token-usage / system-config / data-health / quality-dashboard / bad-cases / eval-suite / shadow / strategy-backtest / capability-center |

**关键调整**：`health-v2`（全账户诊断，`hot: true` 核心功能）从「系统治理」**移至「家庭财务」组**，避免被 devOnly 误伤；`health`（健康分，与 health-v2 重叠）归 🟡 下沉。

**涉及文件**：
- `frontend/src/navigation.js` — 数据层：加 `hidden`/`devOnly` 标记 + `isDevMode()` / `setDevMode()` / `getVisibleNavItems()`
- `frontend/src/components/layout/Sidebar.vue` — 用 `getVisibleNavItems()` 过滤 + 底部加「开发者模式」切换按钮
- `frontend/src/mobileNavigation.js` — 新增 `getVisibleMobileMoreGroups()`
- `frontend/src/components/MobileApp.vue` — 「更多」菜单按 devMode 过滤 + footer 加「开发者模式」切换

### 1.2 死代码清理

- 删除 `backend/agent/orchestrator.py.bak`（196KB 残留备份）
- 删除空目录 `backend/agent/orchestrator/`

### 1.3 后端配置开关

保留现有 config flag，**本轮不关路由**（dashboard 等核心页引用大量分析 API，关路由会破坏引用）。治理组对应 API 保留运行。

## 待实施：阶段 3 AI 对话双引擎收敛（高风险，需单独审批）

### 病灶
1. **双引擎**：`agent/core/pipeline.py`（3513 行，6 阶段，`pipeline_enabled` 默认 true）主路径；`agent/core/orchestrator.py`（7091 行，ReAct）兜底。入口 `orchestrate_stream()` 先试 pipeline，降级走 ReAct。
2. **耦合**：pipeline 反向 import orchestrator 的 6 个函数，不能独立删除。
3. **orchestrator 独有职责**：`wait_for_confirm` 人机确认环、`_schedule_auto_evaluation` 自动评测、`run_peer_review`、`resolve_confirm`、checkpoint 断点恢复。
4. **数据 bug**：`agents` 表 `market_analyst` **重复 2 条**（id=7 preset=1「择时分析师」/ id=13 preset=0「市场分析师」），dict 存储同名 key 后者覆盖前者。
5. **交叉审阅触发逻辑散落**：`should_run_cross_review` / `_detect_specialist_disagreement` / `detect_conflicts*` 多个判断函数。

### 方向（保守，不删代码式大重构）
- 明确架构定位：**pipeline 主路径，orchestrator 为 fallback + 共享工具库**，文档固化。
- 修复 `market_analyst` 重复 key。
- 交叉审阅触发逻辑抽单一入口 + 补注释。

> ⚠️ 涉及 7091 行核心编排，必须单独出方案、单独审批、单独执行。
