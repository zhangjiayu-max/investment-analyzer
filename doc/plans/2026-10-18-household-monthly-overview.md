# 家庭月度总览设计与实施

**目标**：按月份看清家庭固定负担、已经支出、还需支付与资料完整度。沿用现有账单、实际记录和安全预算计算，不改写用户真实账目。

**事实**：当前 5 笔每月必缴账单合计 6742.14 元，均已登记支付；车贷 6364.87 元、保险 377.27 元。原“负债 / 月供”只汇总贷款分类，模板修改保留已支付历史，因此不能期待保险修改改变月供。月收入、全月预算未填写，原 UI 将支出预测隐藏、又展示负结余告警，造成数字无变化和错误暗示。

**方案**：保留资产与投资视图，以月度收支为主线补上月份选择和固定账单明细。对比只修标签、完整重建资产负债系统，这次采用现有数据模型上的月度总览升级；避免引入未经登记的贷款本金。

**接口**：`get_cashflow` 在既有字段外返回 income_known、expense_estimate_complete、known_expense、recorded_debt_payment、pending_debt_payment、variable_total、recurring_paid/pending/due_total、recurring_count、recurring_bills、recurring_by_category、monthly_provision。账单明细含支付快照与当前模板金额/频率，能解释模板调整后已支付金额不变。所有账单与实际数据继续使用同一 SQLite 读事务。

**界面**：
- 财务总览选择月份；当月账单修改后刷新该月份，切换月份时旧请求不得覆盖新月。
- 家庭现金流展示已知支出估算，即使未填收入；资料不足标为“至少已知”，不伪装完整预测。预计结余和投资额度保持资料门槛。
- 新“固定账单”卡展示月均固定负担、本月应付总额、已付、待付、分类和逐笔状态；本月与当前资产范围明确。
- “负债”改为“贷款还款”，拆分已还和待还，注明不含保险，也不是贷款本金。
- 支出弹窗跟随总览月份，保存后刷新总览；未知收入不生成负结余断言。提醒“模板影响未支付账单，已支付保留实付快照”。

**验证步骤**：
- [x] 先新增后端回归：已付车贷+保险、修改已付模板、本月与下月差异、停用与用户隔离、缺收入时已知支出/告警、API 月份与无效输入。
- [x] 实现共享字段、月份接口和还款分项，保留旧字段兼容资金桶/诊断。
- [x] 新增前端回归：未知收入仍能看支出、月份切换竞态、账单更新联动、明细与金额、弹窗月份同步。
- [x] 更新组件并运行相关后端/前端测试、构建 static、实际页面只读验证与截图。

不删除、不重新支付真实记录；不擅自补写收入、预算、贷款本金。未登记生活开销仍需用户补录。

验证结果：后端月度/周期及资产口径相关测试 120 项通过，前端相关测试 69 项通过，Vite 构建成功。实际页面 2026-10 显示固定负担 6742.14 元、本月应付 6742.14 元、已付 6742.14 元、待付 0 元；2026-11 显示已付 0 元、待付 6742.14 元。贷款还款 6364.87 元，非贷款固定账单 377.27 元。
