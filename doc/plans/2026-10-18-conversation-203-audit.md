## 3. Agent 系统问题

### P1：自我反思重试可以把分析替换成无效工具标签

风险管理师 primary run 1265，最终 `result` 为 665 字工具调用 XML，形式是 `<tool_call_36a8...><function=query_valuation>...`，没有风险结论。工具审计也没有执行这段 XML 中的 `query_valuation`。

代码根因可直接对照：

- `multi_agent.py:283` 的文本工具解析只支持固定 `<tool_call>` 和 DSML；带 ID 后缀的标签不被识别。`_has_raw_toolcall_tags`、收口条件和清理器也未完整覆盖此形式。
- `multi_agent.py:885` 的自我反思重试只要文本长度大于 50，就覆盖原答案并标记 `gaps_resolved=True`；没有检查是否为工具调用、是否完整、是否真的补齐缺口。
- `multi_agent.py:901` 的失败检测以少数兜底句和长度为主，665 字 XML 因而被判 `success`。

行为专家 primary run 1267 的重试结果在“（来源：知识库”处中断。对应调用 completion 恰好 4000 tokens，源码也把该重试上限写为 4000，且未检查 `finish_reason`。这高度符合输出截断，但原始 finish_reason 未落库，不能将推断冒充原始响应记录。

建议：重试结果先做结构、工具标签、完整性与证据验证；不合格时保留上一版有效分析，记录重试失败。模型声称解决缺口不能替代验收。

### P1：收敛条件过宽，流程完整性没有成为硬门槛

`multi_agent.py:454` 允许“已有两份非空工具预览”就视为收敛。本次三位专家均在 turn1 被注入收口提示。这只是已有数据，不代表集中度、期限、相关性、压力情景等任务已经完成。

全局反思明确发现风险结论缺失和行为回答截断，但 `_maybe_rerun_specialist`（`pipeline.py:2199`）仅在 `confidence_adjustment < -0.2` 时触发。此次 -0.15 因而不重跑。关键专家无效应直接触发补救或降级，不能取决于 LLM 给出的整体扣分幅度。

### P1：反思自身出现事实错误，综合阶段没有对原始工具复核

审计日志 3814 和消息 metadata 中都保存了：

```json
{"temperature":93,"rate":0.01648,"level":"偏热（债市偏贵，谨慎配置）","date":"2026-10-16"}
```

因此最终报告反复声称“get_bond_temperature 返回空数据”是明确事实错误。数据日期也是最近交易日，应标注日期；93°不等于概率或回撤幅度。

`pipeline.py:2890` 的反思输入来自黑板摘要和专家文本，没有直接附上完整原始工具证据；综合阶段又将反思发现作为需修正的问题注入。可观察到的错误链是：**有效工具数据 → 反思误报无数据 → 综合照抄误报**。不能称原始工具故障。

建议：为反思提供工具证据清单和引用 ID；“工具无数据”“来源冲突”等可核验结论先用程序对照记录。审查意见本身也必须可被原始事实纠正。

### P1：方向共识、风险审查结论、置信度未统一

仲裁因两个专家同为 hold 判 high（`arbitration.py:197`），但风险专家为 unknown，且各方对减持金额、现金投入、黄金目标存在实质分歧。总体方向相同不代表执行方案达成共识。

同一次结果出现三种置信表达：

- answer 事件及结论 128：`confidence=0.55`；
- 仲裁：`high`；
- 用户可见报告：总体置信度“中高”。

另外，answer 事件中的资产配置/行为专家分别是 hold、0.72/0.75；消息 metadata 的专家卡片却全部为 unknown、0。`specialist_done` 事件未携带这些字段，producer 用默认值写入 metadata（`conversations.py:2149`），没有从最终专家对象补齐。

建议：区分方向共识、标的动作一致性、数据充分度和输出完整性；以统一结构生成 UI、存储和报告中的置信度，不允许缺失事件字段覆盖已有结构化结果。

### P1：整体 hold 绕过具体减持动作的守卫

本次日志明确显示 sell_timing_guard 因整体仲裁 hold 而跳过检查（`sell_timing_guard.py:184` 附近），但最终报告确实建议减持 014846。

| 持仓市值 | 521,756.13 元 |


| 卖出金额 | 实际占剩余持仓 |

| 45,000 元 | 23.84% |
| 55,000 元 | 22.21% |
| 63,000 元 | 20.86% |
| 约 67,904.57 元 | 20.00% |

若资金立即买入其他基金、持仓总额保持不变，则是另一种情景，必须明确资金去向。报告没有建立这一前提，也不能一边称占持仓、一边按不变分母计算。

按粗分类，剔除黄金后的指数基金占总资产约 20.12%；混合基金另占 1.58%，实际股票比例需穿透，不能把全部混合基金净值直接视为股票敞口。

| 从现金新增权益 | 指数权益代理比例，及将混合基金全部计入时的上界 |

| 0 | 20.12%–21.71% |
| 12 万 | 31.80%–33.38% |

报告称“25 万会升至约 35%，所以选 12–15 万”不成立。12–15 万方案仍明显偏离原目标 15%；若目标要提高，必须明确这属于风险预算变更，不能称符合原 KYC。

画像还记录资金用途“闲置资金”、流动性需求“1 年内不动”、月支出 5000 元，报告未有效利用这些信息，又把 10–15 万写成“3–6 个月生活备用金”；按已有支出数据实际对应 20–30 个月。资料可复核，但不能当作完全未知后凭空填写规模。

### P1：历史分析未随持仓变化失效

日志记录注入最近 24h 的 5 条结论。按运行时间回溯，包含结论 123–127；其中 127 的 panorama 是当日 14:08:44 的报告，使用“014846+014847 合计 51%、债券 66.3%、估值分位 15%”等旧状态；125 的债券报告使用现金约 22 万，而本次工具现金为 50.59 万。

`orchestrator.py:4633` 主要按 24h 时间窗加载，未以持仓快照版本验证这些结论是否仍适用。最终答案虽部分注明旧数据冲突，但仍继承其估值前提、风险框架和措辞。

本次错误答案又被存为结论 128，置信度 0.55，有效至次日。后续复用可能再次传播“债市工具无数据”等错误。建议历史结论绑定 snapshot_id/持仓指纹、价格日期、来源与验证状态；事实变化后保留观点但废弃旧数量结论。

### P2：交易笔数不能支持“卖赢留亏”与近期心理诊断

`query_transaction_history(limit=30)` 返回 26 买、4 卖，总额 74,000/27,943.72 元。此为最近 30 条记录，不是最近 30 天。审计预览中最近成交日期为 **2026-08-16**。

只读查询确认：以 2026-10-18 为基准，最近 30 天排除系统/假设交易、只计 confirmed/settled，成交数为 **0**。因此行为专家的“近30天20笔买入、0笔卖出”不符合该数据库记录；8 月交易也不应表述为当前两周行为。

买入多、卖出少本身不能证明卖赢留亏。应核对卖出时的已实现收益、卖出与持有的相对收益、时间窗、交易计划和原因。KYC 中已有的行为标签是待验证背景，不能用来把猜测包装成当次诊断。

## 5. 知识库与 RAG

### 正常工作的部分

- 定向查询“组合风险/集中度/资产配置”找到了全天候、全球配置等知识；行为查询找到了损失厌恶、参照点和处置效应，主题匹配较好。

### P1：知识内容本身存在可计算错误，仍标为强证据

知识条目 **3890**《资产配置的艺术：保护型资产配置比例对下跌缓冲效果》进入风险专家检索，`evidence_level=strong`、rerank_score 约 0.981。

条目说：传统资产跌 30%、保护资产涨 10%，各占 50%，组合收益是 +5%。按条目自身给出的加权公式，结果应为：

```text
50% × (-30%) + 50% × 10% = -10%
```

同一条目又把传统跌 20%、保护涨 5%、50/50 配置写成 +40%，简单加权应为 -7.5%。原书是否另含杠杆或其他定义，当前条目没有交代清楚，需回原文核对。

条目 9903 也同时写“非美债券平均约 17.5%、美股平均约 28%”与“非美债券始终最大”，内部叙述矛盾。不能将提炼后的书籍条目无条件升级成可执行强证据。

本次最终报告没有直接引用 3890 的错误收益数字，不能声称它已经造成某个具体最终数值错误；但这足以证明当前入库质量门槛不足。重排衡量相关性，不验证内容正确性。

建议：对知识原子增加公式/比例校验、原书页码或段落锚点、提取模型版本、人工/自动验证状态；存在内部矛盾的条目应降级或隔离，不能靠提高检索相关分解决。

### P2：主问题检索偏向交易规则，相关性弱也被计为覆盖充分

主问题的 7 个命中中包含：月度交易止损规则、年化收益 20%–40% 的交易预期、小盘基金 80% 持仓规则、可口可乐历史集中建仓等。它们与当前家庭基金组合均衡性问题适配较弱。

例如 rerank_score：小盘持仓规则约 0.0089、可口可乐约 0.0010、头寸规模约 0.0941。这些分数不是概率，但在同一批结果中已明显偏低，仍保留并且 `rag_low_quality=0`。

`rag.py:225` 按 `rerank_score + personal_boost` 排序，个性化加分可超过语义分数；此前 RRF 与词重叠阈值不能等价于重排后的相关性验收。`conversations.py:3039` 更把“检索到任意结果”直接计为 rag_coverage=1。

建议先根据意图拆解：当前资产事实、风险约束、资产配置原理、行为背景分别检索；设置重排后的最低质量门槛和适用场景过滤，个性化加分在通过相关性筛选后使用。覆盖率应按待回答的子问题/结论计算。

### P2：进入模型的检索内容损失了来源与完整条件

`tools/__init__.py:2180` 最终向专家返回的 slim 结果只包含类型、标题、300 字预览和融合分；未保留 reference_id、原始来源、章节/页码、适用限制等字段。ReAct 又将工具结果截到 1500 字，并可能将旧结果压到 200 字。

5 条知识的总内容很容易在 JSON 中途被切断；FTS 分词空格还会消耗预览长度。按标题回查原文也不能稳定替代按唯一引用 ID 回查。

因此出现“来源：知识库检索结果”这样的弱引用。能够召回不等于模型拿到足够正文，更不等于结论已被该正文支持。建议保留稳定 evidence_id 与条目来源，按完整条目做 token 预算，支持按 ID 取完整条件。
