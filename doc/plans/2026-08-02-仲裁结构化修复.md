# 仲裁结构化修复 + 主专家机制设计稿

> 日期：2026-08-02
> 背景：conv#196 仲裁方向误判（专家"持有+定投"→仲裁"卖出/减仓"），根因为专家无结构化 verdict 输出 + 仲裁无视结构化信号 + 字段名不匹配 + 无主专家机制
> 目标：结构化数据契约消除幻觉 + 仲裁基于结构化字段裁决 + 主专家机制保障用户需求满足度

## 一、问题根因（调研结论）

### P0-1 仲裁方向误判（致命）
| 层 | 问题 | 位置 |
|----|------|------|
| 专家层 | `run_specialist` 返回 dict 顶层无 `verdict`/`confidence` 字段 | `multi_agent.py:923-934` |
| prompt 层 | `_A2A_OUTPUT_INSTRUCTION` 不要求 LLM 输出 verdict，只要求 action_signals | `message_protocol.py:251-282` |
| 数据类层 | `AgentOutput` 无 verdict 字段 | `message_protocol.py:42-105` |
| 仲裁层-规则 | `arbitrate_results` 只读 analysis 文本，无视 structured.action_signals | `arbitration.py:52-213` |
| 仲裁层-LLM | `_run_react_arbitration` 只取 analysis 前 500 字，无视结构化字段 | `orchestrator.py:1877-1884` |
| 仲裁层-LLM | LLM 仲裁输出 `direction`，下游读 `verdict`——字段名不匹配 | `orchestrator.py:1904-1914` vs `conversations.py:1857-1862` |
| 仲裁层-LLM | prompt 硬性规则"risk_assessor 反对则 BUY 降级 HOLD"系统性压低 | `orchestrator.py:1899` |
| 持久化层 | `_persist_agent_conclusions` 写死 confidence=0.7 | `orchestrator.py:3783` |

### P0-2 仲裁-专家一致性无校验
仲裁方向与专家多数 verdict 相反时无任何告警/复审机制。

### P1-1 用户需求偏离
路由器无主专家概念（全代码库搜索 `primary_specialist` 无命中），`_secondary_route_by_article` 追加 risk_assessor 后文章解读退为配角。

### P2-1 specialist_results 无结构化契约
无 Pydantic/TypedDict 约束，schema 因代码路径而异，下游只能 `.get()` 防御性访问。

## 二、修复方案

### 修复1（P0）：专家结构化 verdict 输出
**目标**：专家 LLM 显式输出 verdict + confidence，结构化字段提升到 specialist_results 顶层。

**改动点**：
1. `message_protocol.py` `_A2A_OUTPUT_INSTRUCTION`：JSON 模板新增 `verdict` 字段（buy/hold/sell/watch/avoid）
2. `message_protocol.py` `AgentOutput` 数据类：新增 `verdict: str` 字段
3. `message_protocol.py` `parse_agent_output`：解析 `verdict` 字段
4. `multi_agent.py` `run_specialist`：返回 dict 顶层新增 `verdict`/`confidence`（从 structured 提升到顶层，下游直接读）

**数据契约**：
```python
# specialist_results[i] 新增顶层字段
{
    "agent_key": "article_expert",
    "agent": "文章解读专家",
    "analysis": "...",          # 原有：Markdown 分析
    "verdict": "hold",          # 新增：buy/hold/sell/watch/avoid（从 structured 提升）
    "confidence": 0.7,          # 新增：0.0-1.0（从 structured 提升）
    "action_signals": [...],    # 新增：结构化操作信号（从 structured 提升）
    "structured": {...},        # 原有：完整结构化输出（保留向后兼容）
    ...
}
```

**verdict 取值规则**（归一化）：
- LLM 输出 `verdict: "buy"` 或 `action_signals[0].type in ("BUY","ADD")` → `"buy"`
- LLM 输出 `verdict: "sell"` 或 `action_signals[0].type in ("SELL","REDUCE")` → `"sell"`
- LLM 输出 `verdict: "hold"` 或 `action_signals[0].type == "HOLD"` → `"hold"`
- LLM 输出 `verdict: "watch"` 或 `action_signals[0].type == "WATCH"` → `"watch"`
- LLM 输出 `verdict: "avoid"` → `"avoid"`
- 无结构化输出 → 回退到 `_detect_stance(analysis)` 关键词检测

### 修复2（P0）：仲裁基于结构化字段裁决
**目标**：仲裁优先读专家结构化 verdict，而非 analysis 文本。

**改动点**：
1. `arbitration.py` `arbitrate_results`：
   - `stance = result.get("verdict") or _detect_stance(analysis)`（优先结构化）
   - 日志记录 stance 来源（structured / keyword_fallback）
2. `orchestrator.py` `_run_react_arbitration`：
   - 专家信息注入改为：`verdict + confidence + analysis 前 800 字`（从 500 扩到 800）
   - 移除"risk_assessor 反对则 BUY 降级 HOLD"硬性规则，改为"参考风险提示，但方向由专家多数 verdict 决定"
3. `orchestrator.py` LLM 仲裁 prompt：输出字段从 `direction` 改为 `verdict`，新增 `key_conflicts`/`reasoning`，与轻量仲裁 + `_save_final` 对齐

**统一仲裁输出契约**：
```python
# 两条路径（规则 / LLM）统一输出
{
    "verdict": "建议卖出/减仓",     # 中文 verdict（轻量仲裁风格）
    "confidence": "high",          # high/medium/low（轻量仲裁风格）
    "key_conflicts": [...],        # 分歧列表
    "reasoning": "...",            # 裁决理由
    "arbitration_mode": "consensus",  # consensus / conflict
    "expert_verdicts": [           # 新增：各专家 verdict 快照（可追溯）
        {"agent": "风险管理师", "verdict": "hold", "confidence": 0.7},
        {"agent": "文章解读专家", "verdict": "buy", "confidence": 0.6},
    ],
    "stance_source": "structured",  # 新增：stance 来源（structured / keyword_fallback）
}
```

### 修复3（P0）：仲裁-专家一致性校验
**目标**：仲裁方向与专家多数 verdict 相反时降级置信度 + 标注。

**改动点**：
1. `arbitration.py` 新增 `_check_consistency` 函数：
   - 统计专家 verdict 多数（buy/hold/sell）
   - 若仲裁方向与多数相反 → confidence 降一级（high→medium，medium→low）+ reasoning 追加"⚠️ 仲裁方向与专家多数不一致"
2. `arbitration_guard.py`：一致性校验时读 `expert_verdicts` 字段，而非从综合报告文本提取

### 修复4（P1）：路由器主专家机制
**目标**：明确主专家，综合合成以主专家 analysis 为主体。

**改动点**：
1. `router.py`：
   - 路由结果新增 `primary_specialist` 字段
   - 纯链接场景 / 文章关键词 → `primary_specialist="article_expert"`
   - 估值关键词 → `primary_specialist="valuation_expert"`
   - 风险关键词 → `primary_specialist="risk_assessor"`
   - 通用 → `primary_specialist=specialists[0]`
2. `orchestrator.py` `_secondary_route_by_article`：保留 primary_specialist
3. `orchestrator.py` 综合合成 prompt：注入 `primary_specialist` 提示"以{主专家}的分析为主体，其他专家为辅助视角"

### 修复5（P2）：specialist_results 结构化契约
**目标**：Pydantic 模型约束，消除字段缺失幻觉。

**改动点**：
1. `message_protocol.py` 新增 `SpecialistResult` Pydantic 模型（轻量，不破坏现有 dict 流转）：
   ```python
   class SpecialistResult(BaseModel):
       agent_key: str
       agent: str
       icon: str = ""
       analysis: str = ""
       verdict: str = "unknown"  # buy/hold/sell/watch/avoid/unknown
       confidence: float = 0.0
       action_signals: list = []
       status: str = "completed"
       tool_calls: list = []
       duration_ms: int = 0
       is_cross_review: bool = False
       is_arbitration: bool = False
   ```
2. `run_specialist` 返回时用 `SpecialistResult.model_validate(dict).model_dump()` 归一化（填充默认值，保证字段完整）
3. 持久化 `_persist_agent_conclusions`：读 `sr["confidence"]` 替代写死 0.7

### 修复6（P2）：tool_calls 字段归一化
**改动点**：
1. `conversations.py` `_save_final`：持久化前归一化 tool_calls 字段名（`tool` → `name`）
